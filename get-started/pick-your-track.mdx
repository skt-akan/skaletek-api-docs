People use Skaletek in different ways. An analyst reviews alerts all day. A rule author tunes thresholds once a week. A developer connects systems during setup. These docs offer three reading tracks, so you see what matters to your role first.

A track is a starting point, not a wall. Every page stays open to everyone. Each page shows badges for the tracks it serves, so you know at a glance whether it is for you.

## The three tracks

| Track | For you if you are… | You learn how to… | You do not see by default |
| --- | --- | --- | --- |
| **Compliance & Operations** | A compliance analyst, compliance officer or money laundering reporting officer (MLRO), fraud investigator, team lead, or procurement or vendor manager | Read an alert, decide what to do, document your work, file a report and prove compliance to an examiner | Code, API calls or technical settings |
| **Configure** | A rule author, template designer or tenant admin | Describe your data, write and test rules, set thresholds, design reports and manage users | Code or raw API requests |
| **Build** | An integration engineer or developer | Authenticate, send events, receive webhooks, handle errors and use the API reference | Compliance theory: terms link to the glossary |
