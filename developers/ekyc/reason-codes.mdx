Reason codes explain why an electronic know your customer (eKYC) verification got its decision. You find them in `reason_codes` on `GET /v1/verifications/{verification_id}` and in the **eKYC Verification** event. See [Receive verification results](/developers/ekyc/receiving-results).

<Note>
  This list can grow. Codes not listed here may appear, for example `POLICY_PASSED`, which means all checks passed. Store reason codes as plain strings and don't reject unknown ones.
</Note>

## Effects

Each code has an effect on the verification:

| Effect | Meaning |
| --- | --- |
| `INFO` | Recorded for context. It does not change the decision on its own. |
| `REVIEW` | A person needs to look at it. The decision becomes `PENDING_REVIEW` unless a failed check rejects the verification. |
| `FAIL` | The check failed. Depending on the workflow, the applicant retakes the step or the verification is rejected. |

Branch your own logic on `decision`, not on reason codes. Use reason codes to explain a decision to your team or to decide what to ask the customer for next.

## Workflow rule codes

Admins can add rules to a workflow, for example to send a weak face match to review. When a rule applies, its code is added to the reason codes. The rule sets the effect.

| Code | Step | Meaning |
| --- | --- | --- |
| `RULE_DATA_MISMATCH` | Reading the document | The data read from the document does not match |
| `RULE_LOW_EXTRACTION_CONFIDENCE` | Reading the document | The document was read with low certainty |
| `RULE_UNSUPPORTED_DOCUMENT` | Document type | The workflow does not accept this document |
| `RULE_FOREIGN_LOCATION` | Country check | The applicant connected from another country |
| `RULE_UNDERAGE` | Reading the document | The applicant is under the workflow's minimum age |
| `RULE_DOCUMENT_EXPIRING` | Reading the document | The document expires soon |
| `RULE_DATA_CORRECTED` | Applicant data review | The applicant corrected data read from the document |
| `RULE_TAMPERING` | Forgery check | Signs of document tampering |
| `RULE_SPOOF_SUSPECTED` | Liveness (face scan) | Suspected spoofing during the face scan |
| `RULE_WEAK_FACE_MATCH` | Face match | Weak face match |

## Country codes

Country fields in the eKYC API, such as `nationality`, `jurisdiction` and `issuing_country`, take lowercase ISO 3166-1 alpha-2 codes, for example `sn` for Senegal and `fr` for France. Skaletek accepts 249 country codes.
